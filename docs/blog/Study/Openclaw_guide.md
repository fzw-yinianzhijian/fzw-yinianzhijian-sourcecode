这篇我想写成“真正在用的人写给刚上手的人”的版本。原因很简单：我自己这段时间用 openclaw 做博客、改文件、跑命令，确实省了不少重复劳动；但刚开始那几天也踩了不少坑。官方资料能告诉你“它能做什么”，我更想补的是“第一周到底该怎么用，才不容易翻车”。

先用一句话讲给新手：**openclaw 不是聊天玩具，而是一个能调用本机工具的执行型助手**。你给它目标，它可以在权限范围里读写文件、执行 shell、操作浏览器、整理结果。重点在“可落地”：不只是回答你，还能把事情做出来。对初学者来说，不用一口气学完全部能力，先跑通最小闭环最关键。

我的最小上手路径是四步，照着走基本不会偏：

1. 先把基础环境跑起来（依赖、启动、工作目录确认）。
2. 给一个超小任务：新建 markdown、写两段话、再读回校验。
3. 再加一层动作：让它执行 `git add` 和 `git commit`，确认不只是“会说”。
4. 最后再碰进阶能力：浏览器接管、消息通知、定时任务。

只要你能连续完成“写文件 → 回读核对 → 执行命令 → 看到可验证结果”，就算真正入门了。

我目前最常见的坑位有这几个：

- **坑 1：目录错位。** 任务说的是这个仓库，实际命令跑在另一个目录，结果改了半天不生效。
- **坑 2：目标太大。** 一上来就要全自动全流程，失败率很高。拆成小步，成功率会明显提升。
- **坑 3：只执行不验收。** 写完不回读、命令不看退出码，最后很容易“看起来完成，实际有错”。
- **坑 4：Git 权限后置处理。** 本地 commit 正常，push 才发现 key 或远端没配好，节奏直接断。

下一部分我会写我自己在“博客维护”场景里的实战模板：怎么下指令更稳定、怎么做提交前检查、以及我现在固定使用的一份防错清单。先把路走通，再谈高级玩法。
